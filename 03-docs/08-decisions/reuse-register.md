# Reuse Register — Previous Implementation, Artifact by Artifact

**Document type:** Decision record — approved reuse classification
**Recorded by:** Task LRG-DEC-004
**Date:** July 25, 2026
**Status:** **APPROVED**
**Governing decision:** `frontend-architecture-decision.md` (FE-ARCH-001 — Option B, Selective Reuse)
**Vocabulary:** exactly as defined in root `CLAUDE.md` §6 — **KEEP · KEEP AND RESTYLE · REFACTOR · MERGE · REPLACE · ARCHIVE · KEEP AS REFERENCE**

`DELETE AFTER CONFIRMATION` is deliberately **not used**. Deletion requires a separate approved cleanup task.

**Reading rules**

- **KEEP** — carry forward substantially as-is; changes are additive or cosmetic.
- **KEEP AND RESTYLE** — logic and contracts survive; visual layer is re-derived from the design system.
- **REFACTOR** — the artifact survives but its internals or contract must change materially.
- **MERGE** — two or more artifacts collapse into one.
- **REPLACE** — rebuilt from an approved source; the old version is retained as reference until an approved cleanup task removes it.
- **ARCHIVE** — retained for history, not used going forward.
- **KEEP AS REFERENCE** — read-only evidence; never a requirements source.

**Every REPLACE and REFACTOR row names what must be preserved.** No artifact carries two conflicting decisions.
