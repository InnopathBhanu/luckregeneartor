# SEO / GEO / AEO Inventory — LotteryCorner (reference project)

Discovery of existing SEO behavior in `00-reference-existing-project/LotteryCorner40`. Read-only;
reference project not modified. No UI/API built. Cross-refs: `01-url-inventory.md`,
`03-revenue-inventory.md`, `13-...`, and the SEO/GEO/AEO requirements in `CLAUDE.md`.

> **Rendering model:** classic **server-side JSP + Struts** (`s:property`). Titles, meta, H1, result
> tables, breadcrumbs, and schema are emitted in server HTML — good baseline for crawlers and AI answer
> engines. Not a client-side SPA.

> **Results-page clarification (per Bala):** there is **no separate dedicated "results page" route** as a
> distinct page type. The **state page is the default latest-results page**, and **date-specific results
> are served by the same state results page/action via a date parameter** — not a separate URL. So the
> SEO items below that mention "result pages" refer to the **state page** (`/{state}`) and **game page**
> (`/{state}/{game}`) / **history** (`/{state}/{game}/{year}`), not a standalone results route. Do not
> add SEO for a separate results-page route unless discovered later or approved by Bala. See `01-...` §5.

## 1. Title generation
- Per-URL, **DB-driven**: `<title><s:property value="seoMetaInfo.pageTitle"/></title>` from `SEOMetaInfo` (entity `SEOMeta`, pojo `SEOMetaInfo`: `pageUrl, pageTitle, metaDescription, metaKeywords, h1Tag, seoHeadingsMap`), cached in `SEOMetaHeadingsCache`, admin-managed via `AddSEOMetaInfoAction` / `addSEOMetaInfo.jsp` / `editSEOMetaInfo.jsp`.
- **Fallback** when no DB row: templated title, e.g. state page falls back to `<selectedState> (…)`. So titles are unique per indexed URL when a row exists; generic otherwise.

## 2. Meta description generation
- Same mechanism: `<META name="description" …>` from `seoMetaInfo.metaDescription`, with a templated fallback. `metaKeywords` also stored (low SEO value today).

## 3. Canonical URL behavior
- State page: `<link rel="canonical" href="https://lotterycorner.com/<stateCode.toLowerCase()>"/>` — **no-www, no trailing slash**.
- **Inconsistency (risk):** BreadcrumbList JSON-LD and OG tags on the same page use `https://www.lotterycorner.com/<state>/` — **www + trailing slash**. Canonical vs schema/OG host+slash disagree. See `01-...` §15.
- Canonical is set per-template; confirm every page type emits one (home/game/history/blog/news/static).

## 4. H1 and heading patterns
- `SEOMetaInfo.h1Tag` + `seoHeadingsMap` (`SEOHeadings`) → per-URL H1 and section headings are DB-driven and admin-editable. Allows unique H1 per page. Fallback H1 templated from state/game name.

## 5. Sitemap
- **Static file** `WebContent/sitemap.xml` — **9,246 `<loc>`** entries (single sitemap, not an index): ~8,700 history (`/{state}/{game}/{year}`), ~477 game (`/{state}/{game}`) + blog/news posts, ~69 one-segment (states, multi-state games, static).
- Regenerated by **admin action** `addsitemapxml` → `AddSiteMapXmlAction` (`addSiteMapXml.jsp`), not automatically on each result update.
- `rss.xml` (static, 283 KB) + `/feed` (`RssFeedAction`) provide a feed.
- `BingSiteAuth.xml` present (Bing verification).

## 6. robots.txt
```
User-agent: Mediapartners-Google
Disallow:
User-agent: *
Disallow: /buynow/
Sitemap: https://lotterycorner.com/sitemap.xml
```
- Only `/buynow/` disallowed (correct — affiliate redirect). Everything else crawlable.
- Also served dynamically via `/robots` action.
- **No AI-crawler rules** (no `GPTBot`/`OAI-SearchBot`/`PerplexityBot`/`ChatGPT-User` lines) — see §16.
- Sitemap URL uses **no-www**; site elsewhere uses www — keep host consistent.

## 7. ads.txt
- `WebContent/ads.txt` (Google DIRECT pubs `pub-6009276896057794`, `pub-5258173596915552`, Ampliffy, many resellers) + `ads_google.txt`; served via `/ads` action. Detailed in `03-revenue-inventory.md` §2. **Preserve verbatim.**

## 8. Schema / structured data (JSON-LD)
Present (server-emitted):
- **Sitewide:** `Organization` (name, url, logo, `sameAs` socials) in `commonELements_newVersion.jspf` / `CommonElementsUpgrade_as.jspf`.
- **Per page:** `WebSite` (name "US Lottery Results", url) + `BreadcrumbList` (Home → State, with `WebPage` `@id`s). Counts across result/blog/news JSPs: WebPage 59, ListItem 41, WebSite 18, BreadcrumbList 18, Person 4, Organization 4.
- **Missing:** no `Article`/`NewsArticle` on blog/news posts; no `Dataset`/`DataCatalog` on history/result data; no `FAQPage`; no `WebSite` `potentialAction`/`SearchAction`. See §16.
- OG bug: state page emits `og:image:type="website"` (should be an image MIME type); `og:image:width/height` commented out.

## 9. Breadcrumbs
- Both **visible** (`<div class="breadcrumb">`) and **structured** (`BreadcrumbList` JSON-LD). State breadcrumb = Home → State. Confirm game/history breadcrumbs add Game / Year levels (deeper pages should extend the trail).

## 10. Internal linking patterns
- Strong server-rendered internal linking: state pages link to their games; games link to history (`/{state}/{game}/{year}`); "Winning Numbers by State" grid (`wiiningNumbersByState*.jspf`); popular/multi-state game indexes; footer links (Powerball, Mega Millions, state lotteries, How to Play, Claim, Responsible Gaming). Buy Tickets links go through `/buynow/*` (nofollow-worthy; robots-disallowed).

## 11. Blog / news SEO behavior
- Posts server-rendered at `/blog/{slug}` (`ShowBlogEntryAction` → `blogentry_as.jsp`) and `/news/{slug}` (`ShowNewsEntryAction` → `newsentry_upgrade_as.jsp`); listings at `/blog`, `/news`; tags via `blogsbytag`.
- SEOMeta (title/desc/H1) applies per post URL.
- **No `Article`/`NewsArticle` schema, no visible `datePublished`/`dateModified` structured data** on posts found — GEO/AEO + rich-result gap (§16). Content stored/managed via admin `BlogEntryAction`/`NewsEntryAction`; blog content also under `Resources/Blog/`.

## 12. Crawlability concerns
- Positive: server-rendered HTML, one flat sitemap, minimal robots blocking, `/buynow/` correctly disallowed.
- Concerns:
  - Single 9,246-URL sitemap with **static/manual regeneration** → `lastmod` freshness lag when results update (§14, §16).
  - Broad `*` / `*/*` wildcards can generate thin/soft-404 state/game pages for unknown slugs (`01-...` §15) → crawl-budget/duplicate risk.
  - Canonical vs www/slash mismatch (§3) can split signals.
  - A/B index variants (`index_upgrade_as_special`, `_lazy_testing`) risk duplicate home content if ever exposed at crawlable URLs.

## 13. Client-side vs server-rendered content
- Core content (results tables, jackpots, schedules, claim/tax text, breadcrumbs, schema) is **server-rendered** — good for SEO/GEO/AEO. Ads (GPT/AdSense) and some widgets load client-side, which is fine (ads shouldn't be indexed). No SPA/hydration dependency for main content found.

## 14. Last updated timestamp behavior
- State/game results show a **visible date** via `<s:date name="datePublishedDate"/>` (result publish date). This is a per-result date, effectively a "last drawn/updated" indicator.
- **No machine-readable `dateModified`/ISO timestamp** in schema, and sitemap `lastmod` depends on manual regen — so freshness signals to search/AI are weaker than the visible date suggests (§16).

## 15. Official source attribution & disclaimers
- Affiliate/compliance disclaimer present on result pages: **"Commercial Content | T&Cs apply | Play Responsibly"**.
- Independence/"not affiliated" language appears in proposed mockups (`08/09`) and should be confirmed/standardized here.
- No explicit per-page "official source" attribution block (link to the state lottery as data source) found — a trust/GEO gap (§16).

## 16. Missing SEO / GEO / AEO opportunities
Relative to `CLAUDE.md` requirements:
1. **Fix canonical vs www/trailing-slash mismatch** (§3) — pick one host+slash convention; keep canonical, OG, schema, sitemap, and robots all consistent. (Needs Bala decision — see `01-...` Q5.)
2. **Add `Dataset`/`DataCatalog` schema** to history/result pages (`/{state}/{game}/{year}`) — high AEO value for a results database.
3. **Add `Article`/`NewsArticle` schema** (with `datePublished`/`dateModified`, author, headline) to real blog/news posts only.
4. **Add machine-readable `lastUpdated`** (ISO `dateModified`) alongside the visible date on results/jackpots; wire **automatic `lastmod`** on result updates + move to a **sitemap index** (split by state/game/history/blog); adopt **IndexNow** on updates.
5. **Add `WebSite` `SearchAction`** (sitelinks search box) — currently `WebSite` schema has no `potentialAction`.
6. **Add `FAQPage` schema** where visible FAQs exist (state/game pages have FAQ sections in mockups).
7. **Add explicit `robots.txt` AI-crawler rules** (Googlebot/Bingbot/OAI-SearchBot/PerplexityBot allow; GPTBot per policy) per `CLAUDE.md` baseline.
8. **Short answer / "answer block"** near the top of state/game pages (GEO/AEO) — present in mockups, ensure server-rendered.
9. **Official source attribution** block (link to the state lottery as the results source) on result pages.
10. **Guard the `*` wildcard** — return real 404s for unknown slugs to avoid thin/duplicate indexation; keep A/B home variants non-indexable.
11. Fix `og:image:type` value and restore `og:image:width/height`.

## Preservation notes (carry into rebuild)
- Keep **DB-driven per-URL SEOMeta** (title/description/H1/headings) — replicate as a `SeoTemplate` + per-URL override store; migrate existing rows so indexed pages keep their exact titles/descriptions.
- Keep **server-rendered** main content and breadcrumbs (visible + `BreadcrumbList`).
- Preserve existing **canonical values** during migration; only change host/slash convention with a documented redirect+canonical plan (`01-url-seo-preservation-rules.md`).
- Preserve the **static assets** `robots.txt`, `ads.txt`/`ads_google.txt`, `sitemap.xml`, `rss.xml`, `BingSiteAuth.xml` behavior and URLs.
- Do not index `/buynow/*`, `/admin/*`, or A/B home variants.
